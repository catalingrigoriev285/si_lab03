1. Introducere teoretică

1.1. Anatomia unui apel de instrument extern

În laboratorul anterior ați văzut bucla agentului sub formă de diagramă. Din punct de vedere a informației care circulă efectiv între agent și model, pentru API-ul compatibil OpenAI (standard) care este folosit pentru toți furnizorii, agentul trimite la fiecare cerere trei lucruri: mesajele (istoricul complet), lista instrumentelor și, opțional, o preferință tool_choice.

Cererea (prescurtată):

{
  "model": "gemini-3.5-flash-lite",
  "messages": [
    {"role": "system", "content": "Ești asistentul unei clădiri inteligente..."},
    {"role": "user", "content": "Cât consumă radiatorul în 3 ore?"}
  ],
  "tools": [{
    "type": "function",
    "function": {
      "name": "estimate_energy",
      "description": "Estimează energia consumată (în kWh) de un dispozitiv ...",
      "parameters": {
        "type": "object",
        "properties": {"name": {"type": "string"}, "hours": {"type": "number"}},
        "required": ["name", "hours"]
      }
    }
  }]
}

Dacă modelul decide să folosească instrumentul, nu răspunde cu text, ci cu o cerere de apel:

{
  "role": "assistant",
  "content": null,
  "tool_calls": [{
    "id": "call_1",
    "type": "function",
    "function": {
      "name": "estimate_energy",
      "arguments": "{\"name\": \"radiator\", \"hours\": 3}"
    }
  }]
}

Agentul execută apelul și răspunde cu un mesaj de tip tool, care poartă același id:

{"role": "tool", "tool_call_id": "call_1", "content": "{\"nume\":\"radiator\",\"ore\":3.0,\"energie_kwh\":4.5}"}

Trei lucruri trebuie reținute:

  • arguments este un șir de caractere care conține un JSON, nu un obiect JSON. Modelul îl generează ca text, deci poate fi invalid (ghilimele lipsă, virgulă în plus). Agentul trebuie să-l parseze cu json.loads și să trateze eroarea; codul din secțiunea 3.3 face acest lucru.
  • Modelul nu vede serverul MCP. Vede doar schema instrumentelor (numele, descrierea, parametrii) și rezultatele pe care i le trimitem noi.
  • Cererea către model nu are memorie. La fiecare cerere retrimitem tot istoricul. Ce „își amintește" modelul este exact ce se află în lista messages.

1.2. Apeluri multi per pas

Câmpul tool_calls este o listă: într-un singur răspuns, modelul poate cere mai multe instrumente (de exemplu check_conflict și două apeluri estimate_energy). Agentul le execută pe rând și adaugă în istoric câte un mesaj tool pentru fiecare, cu tool_call_id-ul corespunzător. Apoi trimite totul modelului, într-o singură cerere nouă.

Un model nu poate folosi rezultatul unui apel ca argument al altui apel din același pas: apelurile dependente apar în pași succesivi. Dacă modelul trebuie să afle întâi lista dispozitivelor și abia apoi să estimeze consumul, vom vedea două cereri către model, nu una. Veți putea număra pașii în fișierul de log.

1.3. tool_choice pentru alegerea unui instrument

Valoare Efect
auto (implicit) modelul decide singur dacă folosește instrumente
none modelul nu are voie să ceară instrumente; răspunde doar cu text
required modelul trebuie să ceară cel puțin un instrument

Agentul nostru aplică tool_choice numai la primul pas al fiecărei întrebări. Motivul: cu required la fiecare pas, modelul ar fi obligat să ceară instrumente și după ce are răspunsul, deci n-ar mai putea niciodată să răspundă cu text, iar bucla s-ar opri abia la limita MAX_STEPS.

Atenție la furnizor. Documentația Gemini pentru compatibilitatea OpenAI arată doar tool_choice="auto" (Gemini - OpenAI compatibility). Dacă încercați none sau required și primiți HTTP 400, reveniți la auto. Furnizorul mock suportă toate trei valorile.

1.4. Prompturi folosite pentru descrierea instrumentului

Docstring-urile și adnotările de tip contează: modelul alege instrumentul numai pe baza numelui, a descrierii și a schemei parametrilor. Descrierea este, în practică, un fragment de prompt scris de dezvoltatorul serverului.

Lista instrumentelor se retrimite la fiecare cerere, deci fiecare instrument consumă tokeni din context și din cota voastră. Mai multe instrumente înseamnă și mai multe ocazii ca modelul să aleagă greșit. Vom reveni asupra acestei probleme la componenta referitoarela descoperirea (dinamică) a serviciilor.

1.5. Starea sistemului

Când spunem „agentul își amintește", trebuie să precizăm unde este ținută informația:

Starea Unde persistă Cât durează Exemplu
Conversația lista agent.messages, retrimisă modelului la fiecare cerere până la /reset sau până o finalizăm O întrebare pusă se referă la conversația anterioară
Starea lumii variabilele din procesul serverului MCP cât rulează serverul ce dispozitive sunt pornite
Modelul nicăieri - nu reține nimic între două cereri

Consecință practică: comanda /reset șterge conversația, nu afectează senzorii și instrumnetele din clădirea inteligentă modelată. Un dispozitiv pornit rămâne pornit până se oprește serverul.

Notă despre proiectarea serverelor. Serverul anterior definit ține starea într-o variabilă globală, ceea ce este suficient pentru un laborator cu un singur client. Specificația MCP notează însă că protocolul nu are sesiune implicită și recomandă ca starea persistentă să fie legată de identificatori expliciți, returnați de instrumente și transmiși apoi ca argumente (MCP - Tools, secțiunea „Stateful Tools"). Se va alege această implementare în laboratorul despre expunerea serviciilor.

1.6. Instrumente cu efecte disponibile - utilizare

Un instrument care modifică lumea (pornește un radiator, resetează o clădire sau șterge un fișier - gândiți-vă la un sistem read/write în loc de unul read-only) schimbă situația, pentru că:

  • modelul poate greși (dispozitivul sau valoarea nu sunt cele dorite de utilizator);
  • textul din întrebare sau din rezultatele altor instrumente poate încerca să-l convingă să facă altceva decât a cerut utilizatorul (prompt injection);
  • un efect nu se poate retrage la fel de ușor ca un răspuns greșit.

Specificația MCP spune că ar trebui să existe întotdeauna un om în buclă, cu posibilitatea de a refuza apelurile, și recomandă ca aplicațiile să ceară confirmare pentru operațiuni și să arate utilizatorului argumentele înainte de apel (MCP - Tools). Serverul poate descrie un instrument prin adnotări:

Adnotare Sens Valoare dacă lipsește
readOnlyHint instrumentul nu modifică nimic false
destructiveHint poate face modificări distructive (are sens doar dacă nu e readOnlyHint) true
idempotentHint repetarea cu aceleași argumente nu mai schimbă nimic false
openWorldHint interacționează cu sisteme din exterior true

Documentația FastMCP (FastMCP - Tools). Aceeași pagină precizează că adnotările sunt indicii, nu mecanisme de securitate. Specificația merge mai departe: clienții trebuie să le considere nesigure, dacă serverul nu este de încredere.

Politica default a agentului ar trebui să fie cea de „refuz implicit" (default-deny): cerem acordul utilizatorului pentru orice instrument care nu declară explicit readOnlyHint=true. Un server care uită adnotările sau halucinează în privința lor nu poate fi astfel executat în lipsa confirmării. Dacă agentul nu primește nicio funcție de confirmare, instrumentele cu efecte sunt pur și simplu refuzate.

Un apel cu efecte trece prin trei straturi de protecție:

Strat Unde Ce oprește Exemplu
Schema serverul, înainte de a rula funcția valori de tip sau domeniu greșit set_thermostat(temp_c=50)
Regula de domeniu în corpul instrumentului acțiuni care nu au sens în clădire pornirea aerului condiționat cu radiatorul pornit
Omul agentul, înainte de apel orice altceva „nu am cerut să resetezi clădirea"

3.1. Furnizorul mock: un model fals, de testare

Un model fals (mock) este un înlocuitor care imită interfața modelului real, dar răspunde după reguli simple, fără rețea și fără cheie. Îl folosim pentru că:

  • este repetabil (determinist): aceeași întrebare produce mereu aceleași apeluri, deci putem compara rulări și verifica ce face agentul, separat de capriciile modelului;
  • nu consumă cotă (reamintim limitele cotei gratuite din laboratorul precedent);
  • arată rolul real al modelului: un model de limbaj doar emite o cerere de apel (JSON); tot restul face agentul. Cu mock puteți chiar să jucați voi rolul modelului (vezi exercițiul A4).

Limita furnizorului mock. Nu înțelege limba română și nu citește descrierile instrumentelor. De aceea nu poate arăta cât contează un docstring bun. Pentru acest lucru, și pentru comportamentul „real" al unui model (greșeli, ezitări), aveți nevoie de un model adevărat; acele exerciții sunt marcate cu stringul (model real).

Salvați mock_llm.py:

"""Furnizorul "mock": un model de limbaj FALS, fără rețea și fără cheie API.

Nu înțelege limba română; decide ce instrument să ceară după câteva reguli simple
(cuvinte-cheie) sau după o comandă explicită. Servește pentru teste deterministe.
IMPORTANT: nu citește descrierile instrumentelor, deci nu poate arăta efectul unui
docstring bun sau prost - pentru asta aveți nevoie de un model real.
"""
import json
import re
import unicodedata
from itertools import count
from types import SimpleNamespace

# nume canonic -> forme (fără diacritice) sub care apare în întrebări
DISPOZITIVE = {
    "lampa_led": ["lampa", "led"],
    "radiator": ["radiator", "calorifer"],
    "aer_conditionat": ["aer conditionat", "aerul conditionat", "aer_conditionat"],
    "jaluzele": ["jaluzele", "jaluzelele"],
    "ventilatie": ["ventilatie", "ventilatia"],
    "frigider": ["frigider", "frigiderul"],  # nu există în server: pentru testul erorilor
}
_ids = count(1)


def norm(text: str) -> str:
    """Litere mici, fără diacritice."""
    text = unicodedata.normalize("NFD", text.lower())
    return "".join(c for c in text if not unicodedata.combining(c))


def gaseste_dispozitive(t: str) -> list[str]:
    """Dispozitivele din text normalizat, în ordinea apariției."""
    gasite = []
    for nume, forme in DISPOZITIVE.items():
        poz = [m.start() for f in forme for m in re.finditer(r"\b" + re.escape(f), t)]
        if poz:
            gasite.append((min(poz), nume))
    return [nume for _, nume in sorted(gasite)]


def numar(pattern: str, t: str):
    m = re.search(pattern, t)
    return float(m.group(1).replace(",", ".")) if m else None


def planifica(text: str, unelte: set[str]) -> list[tuple[str, dict]]:
    """Lista de apeluri (nume, argumente) pe care le 'decide' mock-ul pentru o întrebare."""
    t = norm(text)

    # 1. Comandă explicită:  apel: nume {"arg": 1} ; alt_nume {...}
    if t.startswith("apel:"):
        apeluri = []
        for parte in text.split(":", 1)[1].split(";"):
            nume, _, rest = parte.strip().partition(" ")
            apeluri.append((nume, json.loads(rest) if rest.strip() else {}))
        return apeluri

    # 2. Buclă artificială (pentru testul de detecție a buclei)
    if "bucla" in t:
        return [("list_devices", {})]

    # 3. Reguli cu cuvinte-cheie
    dispozitive = gaseste_dispozitive(t)
    ore = numar(r"(\d+(?:[.,]\d+)?)\s*(?:de\s+)?or[ae]?\b", t)
    apeluri = []
    if ("conflict" in t or "acelasi timp" in t or "impreuna" in t) and len(dispozitive) >= 2:
        apeluri.append(("check_conflict", {"device_a": dispozitive[0], "device_b": dispozitive[1]}))
    if any(c in t for c in ("consum", "kwh", "energie")) and dispozitive:
        for d in dispozitive[:2]:
            apeluri.append(("estimate_energy", {"name": d, "hours": ore if ore is not None else 1.0}))
    if dispozitive and any(c in t for c in ("porneste", "aprinde", "activeaza", "deschide")):
        apeluri.append(("set_device_state", {"name": dispozitive[0], "on": True}))
    if dispozitive and any(c in t for c in ("opreste", "stinge", "inchide", "dezactiveaza")):
        apeluri.append(("set_device_state", {"name": dispozitive[0], "on": False}))
    grade = numar(r"(\d+(?:[.,]\d+)?)\s*(?:de\s+)?(?:grade|°)", t)
    if grade is not None and ("termostat" in t or "temperatura" in t or "grade" in t):
        apeluri.append(("set_thermostat", {"temp_c": grade}))
    if "reseteaza" in t or "resetare" in t:
        apeluri.append(("reset_building", {}))
    if "stare" in t or "ce este pornit" in t or "ce e pornit" in t:
        apeluri.append(("get_building_state", {}))
    if "ce dispozitive" in t or "lista" in t:
        apeluri.append(("list_devices", {}))
    if dispozitive and ("informatii" in t or "despre" in t) and not apeluri:
        apeluri.append(("get_device_info", {"name": dispozitive[0]}))
    # Regulile cer doar instrumente care există; comanda explicită (1) nu filtrează.
    return [(n, a) for n, a in apeluri if n in unelte]


class _Apel:
    """Un apel de instrument, cu aceleași câmpuri ca în răspunsul unui model real."""

    def __init__(self, nume: str, argumente: dict):
        self.id = f"mock_{next(_ids)}"
        self.type = "function"
        self.function = SimpleNamespace(
            name=nume, arguments=json.dumps(argumente, ensure_ascii=False)
        )

    def model_dump(self, exclude_none=True):
        return {
            "id": self.id,
            "type": "function",
            "function": {"name": self.function.name, "arguments": self.function.arguments},
        }


def _raspuns(mesaje, continut=None, apeluri=None):
    mesaj = SimpleNamespace(role="assistant", content=continut, tool_calls=apeluri or None)
    chars = len(json.dumps(mesaje, ensure_ascii=False, default=str))
    usage = SimpleNamespace(prompt_tokens=chars // 4, completion_tokens=20)  # estimare grosieră
    return SimpleNamespace(choices=[SimpleNamespace(message=mesaj)], usage=usage)


class _Completions:
    def create(self, model=None, messages=None, tools=None, tool_choice=None, **_):
        unelte = {t["function"]["name"] for t in (tools or [])}
        ultimul = messages[-1]

        # a) Tocmai au sosit rezultate de instrumente: formulăm răspunsul final.
        if ultimul["role"] == "tool":
            ultimul_user = next(m for m in reversed(messages) if m["role"] == "user")
            if "bucla" in norm(ultimul_user["content"]) and "list_devices" in unelte:
                return _raspuns(messages, apeluri=[_Apel("list_devices", {})])
            rezultate = []
            for m in reversed(messages):
                if m["role"] != "tool":
                    break
                rezultate.append(m["content"])
            linii = "\n".join(f"- {r}" for r in reversed(rezultate))
            return _raspuns(messages, continut=f"[mock] Rezultatele instrumentelor:\n{linii}")

        # b) Mesaj nou de la utilizator.
        text = ultimul["content"]
        if tool_choice == "none":
            return _raspuns(messages, continut="[mock] (am răspuns fără instrumente, tool_choice=none)")
        try:
            apeluri = planifica(text, unelte)
        except (ValueError, json.JSONDecodeError):
            return _raspuns(messages, continut="[mock] Comandă 'apel:' invalidă. Format: apel: nume {json}")
        if not apeluri and tool_choice == "required" and "list_devices" in unelte:
            apeluri = [("list_devices", {})]  # 'required' obligă modelul să ceară ceva
        if not apeluri:
            return _raspuns(messages, continut="[mock] Nu am nevoie de instrumente pentru asta.")
        return _raspuns(messages, apeluri=[_Apel(n, a) for n, a in apeluri])


class MockClient:

    base_url = "mock://local"

    def __init__(self):

3.2. Fișierul de log: formatul JSONL

Un agent care apelează instrumente face lucruri pe care nu le vedeți toate pe ecran: câte cereri a trimis modelului, ce argumente a generat modelul, ce eroare a întors serverul. Pentru depanare și pentru comparații avem nevoie de un fișier de log în care fiecare pas este scris într-o formă care se poate citi atât de oameni, cât și de programe.

Folosim formatul JSONL (JSON Lines, extensia .jsonl): un fișier text în care fiecare linie este un obiect JSON complet (monolinie), iar liniile sunt separate prin caracterul de linie nouă. Nu există paranteze în jurul întregului fișier și nici virgule între linii. Fișierul este codat UTF-8 (JSON Lines).

Comparație, pentru aceleași două evenimente. Un singur document JSON (o listă):

[
  {"tip": "apel", "nume": "check_conflict"},
  {"tip": "rezultat", "eroare": false}
]

Același conținut în JSONL, un eveniment pe linie:

{"tip": "apel", "nume": "check_conflict"}
{"tip": "rezultat", "eroare": false}

Avantajele pentru un fișier de log:

  1. Adăugarea este trivială. Un eveniment nou înseamnă o linie nouă la sfârșit. Într-o listă JSON ar trebui să rescriem fișierul sau să ștergem și să rescriem parantezele de la capăt.
  2. Rezistă la crash-uri. Dacă programul se oprește brusc (cădere, Ctrl + C), toate liniile deja scrise rămân valide. Cel mult ultima linie este incompletă. O listă JSON netermiată cu ] nu mai poate fi citită deloc de un parser JSON.
  3. Se citește direct. Se procesează o linie pe rând, fără a încărca fișierul întreg în memorie. Funcționează și pentru fișiere mari, iar site-ul formatului îl recomandă explicit pentru fișiere de log (JSON Lines).
  4. O linie stricată nu strică restul. Fiecare linie se parsează independent; scriptul nostru de analiză sare peste liniile ilizibile.
  5. Este structurat, deci se poate interoga. Spre deosebire de un log în text liber („12:03 am apelat radiatorul"), putem număra, filtra și calcula (apeluri pe instrument, durata medie, evenimente cu eroare) cu câteva linii de cod, fără expresii regulate.
  6. Se poate folosi cu unelte obișnuite. Fiind text cu o înregistrare pe linie, merge cu Select-String (PowerShell) sau grep, se citește în Python linie cu linie și se încarcă într-un tabel (de exemplu cu pandas.read_json(..., lines=True)).
  7. Este rezonabil de lizibil pentru oameni. Un eveniment pe linie se parcurge ușor cu ochiul, ceea ce nu merge pentru un JSON indentat pe sute de linii.

Dezavantaje și precauții: liniile lungi sunt incomode de citit direct (de aceea avem analyze_log.py); formatul nu impune o schemă, deci disciplina câmpurilor ține de cod; și, mai ales, fișierul conține întrebările voastre și rezultatele instrumentelor. Nu-l urcați pe Git și nu-l trimiteți altora fără să-l citiți. Agentul nu scrie niciodată cheia API în log.

reset la crearea unei conversații noi -
intrebare la fiecare întrebare a utilizatorului text, mesaje_taiate
cerere_model la fiecare cerere către model pas, mesaje, durata_ms, prompt_tokens
apel când modelul cere un instrument pas, nume, argumente
confirmare înainte de un instrument cu efecte pas, nume, aprobat
rezultat după execuția (sau refuzul) unui apel pas, nume, eroare, text, trunchiat
raspuns răspunsul final al agentului text, pas
bucla_detectata, limita_pasi când agentul se oprește singur pas / pasi

"""Laborator 2 SI - serverul MCP al clădirii inteligente, acum cu instrumente care modifică starea."""
from typing import Annotated

from fastmcp import FastMCP
from pydantic import Field

mcp = FastMCP("smart-building-demo")

# Date de test, inventate pentru laborator.
DEVICES = {
    "lampa_led": {"categorie": "iluminat", "putere_w": 10, "note": "Se poate regla pe trepte de intensitate."},
    "radiator": {"categorie": "încălzire", "putere_w": 1500, "note": "Controlat de termostatul camerei."},
    "aer_conditionat": {"categorie": "climatizare", "putere_w": 2000, "note": "Nu se folosește cu ferestrele deschise."},
    "jaluzele": {"categorie": "umbrire", "putere_w": 30, "note": "Motor electric, consum doar la mișcare."},
    "ventilatie": {"categorie": "ventilație", "putere_w": 120, "note": "Aduce aer proaspăt din exterior."},
}
CONFLICTE = {
    frozenset({"radiator", "aer_conditionat"}): "RIDICAT - încălzire și răcire simultană, consum inutil.",
    frozenset({"aer_conditionat", "ventilatie"}): "MEDIU - aerul exterior scade eficiența climatizării.",
}

# Starea clădirii. Trăiește în procesul serverului, NU în conversația cu modelul:
# se pierde doar când serverul este oprit.
PORNITE: set[str] = set()
TERMOSTAT = {"temp_c": 21.0}

# Adnotări (indicii pentru gazdă, nu garanții): vezi secțiunea 4.2.
CITIRE = {"readOnlyHint": True}
MODIFICARE = {"readOnlyHint": False, "destructiveHint": False, "idempotentHint": True}
DISTRUGERE = {"readOnlyHint": False, "destructiveHint": True, "idempotentHint": True}


def _necunoscut(name: str) -> dict:
    return {"eroare": f"Dispozitiv necunoscut: {name}", "cunoscute": sorted(DEVICES)}


# ---------- Instrumente de citire (ca în Laboratorul 1) ----------

@mcp.tool(annotations=CITIRE)
def list_devices() -> list[str]:
    """Returnează numele tuturor dispozitivelor cunoscute din clădire."""
    return sorted(DEVICES)


@mcp.tool(annotations=CITIRE)
def get_device_info(name: str) -> dict:
    """Returnează informații de bază despre un dispozitiv (categorie, putere în W, note)."""
    info = DEVICES.get(name.strip().lower())
    if info is None:
        return _necunoscut(name)
    return {"nume": name.strip().lower(), **info}


@mcp.tool(annotations=CITIRE)
def check_conflict(device_a: str, device_b: str) -> str:
    """Verifică dacă două dispozitive au un conflict de funcționare cunoscut."""
    cheie = frozenset({device_a.strip().lower(), device_b.strip().lower()})
    return CONFLICTE.get(cheie, "Niciun conflict înregistrat în setul de date de test.")


@mcp.tool(annotations=CITIRE)
def estimate_energy(name: str, hours: float) -> dict:
    """Estimează energia consumată (în kWh) de un dispozitiv care funcționează un număr de ore."""
    info = DEVICES.get(name.strip().lower())
    if info is None:
        return _necunoscut(name)
    return {
        "nume": name.strip().lower(),
        "ore": hours,
        "energie_kwh": round(info["putere_w"] * hours / 1000, 3),
    }


@mcp.tool(annotations=CITIRE)
def get_building_state() -> dict:
    """Returnează starea curentă a clădirii: dispozitivele pornite și temperatura dorită a termostatului."""
    return {"pornite": sorted(PORNITE), "termostat_c": TERMOSTAT["temp_c"]}


# ---------- Instrumente noi, cu efecte ----------

@mcp.tool(annotations=MODIFICARE)
def set_device_state(name: str, on: bool) -> dict:
    """Pornește (on=true) sau oprește (on=false) un dispozitiv.

    Refuză pornirea dacă ar crea un conflict de nivel RIDICAT cu un dispozitiv deja pornit.
    """
    nume = name.strip().lower()
    if nume not in DEVICES:
        return _necunoscut(name)
    if on:
        for altul in sorted(PORNITE):
            conflict = CONFLICTE.get(frozenset({nume, altul}), "")
            if conflict.startswith("RIDICAT"):
                return {"ok": False, "motiv": f"Conflict cu {altul}, care este pornit: {conflict}"}
        PORNITE.add(nume)
    else:
        PORNITE.discard(nume)
    return {"ok": True, "nume": nume, "pornit": nume in PORNITE}


@mcp.tool(annotations=MODIFICARE)
def set_thermostat(
    temp_c: Annotated[float, Field(ge=10, le=30, description="Temperatura dorită, în grade Celsius (10-30).")],
) -> dict:
    """Setează temperatura dorită a termostatului camerei."""
    TERMOSTAT["temp_c"] = temp_c
    return {"ok": True, "temp_c": temp_c}


@mcp.tool(annotations=DISTRUGERE)
def reset_building() -> dict:
    """Oprește toate dispozitivele și readuce termostatul la 21 °C. Șterge starea curentă a clădirii."""
    PORNITE.clear()
    TERMOSTAT["temp_c"] = 21.0
    return {"ok": True, "mesaj": "Clădirea a fost resetată."}


# ---------- Resursă și prompt (ca în Laboratorul 1) ----------

@mcp.resource("device://{name}/manual")
def manual(name: str) -> str:
    """Un manual (fictiv) de o linie, expus ca resursă."""
    info = DEVICES.get(name.lower())
    return f"{name}: {info['categorie']}. {info['note']}" if info else f"Nu există manual pentru {name}."


@mcp.prompt
def energy_review(devices: str) -> str:
    """Șablon de prompt: cere unui LLM să analizeze o listă de dispozitive."""
    return (
        f"Analizează această listă de dispozitive: {devices}. "
        "Folosește instrumentele pentru a verifica conflictele și a estima consumul."
    )

    mcp.run(show_banner=False)  # stdio, implicit

Față de laboratorul trecut, agent.py primește patru îmbunătățiri:

  • fișierul de log (clasa JsonlLog, evenimentele din secțiunea 3.2);
  • verificări și confirmare în call_tool (le explicăm în Partea B);
  • gestiunea istoricului: trim_history, truncate, detecția buclei (le explicăm în Partea C);
  • un detaliu de corectitudine: când agentul se oprește singur, încheie conversația cu un mesaj al asistentului, nu cu un mesaj tool, ca istoricul să rămână valid pentru cererea următoare.

Salvați agent.py (înlocuiește versiunea veche:

"""Agentul v2: buclă între model și instrumentele unui server MCP, cu fișier de log,
confirmare pentru instrumentele cu efecte și gestiunea istoricului."""
import json
import time
from datetime import datetime
from pathlib import Path

from fastmcp import Client

from llm import create_chat, make_client

SERVER = Path(__file__).parent / "server.py"
LOG_DIR = Path(__file__).parent / "logs"

MAX_STEPS = 6           # limită de siguranță pentru bucla de apeluri într-un singur răspuns
MAX_REPEAT = 2          # de câte ori poate fi cerut ACELAȘI apel (același nume și aceleași argumente)
MAX_TURNS = 6           # câte întrebări (ture) rămân în istoric
MAX_TOOL_CHARS = 1500   # lungimea maximă a unui rezultat de instrument păstrat în istoric
TOOL_CHOICE = "auto"    # auto | none | required - se aplică doar primului pas al fiecărei întrebări

SYSTEM_PROMPT = (
    "Ești asistentul unei clădiri inteligente. Răspunde concis, în limba română. "
    "Pentru informații despre dispozitive, conflicte, consum sau starea clădirii folosește "
    "instrumentele disponibile; nu inventa date. Dacă un instrument returnează o eroare sau "
    "utilizatorul refuză un apel, spune-o clar."
)


class JsonlLog:
    """Fișier de log în format JSONL: un eveniment = o linie JSON, adăugată la sfârșit."""

    def __init__(self, directory: Path = LOG_DIR):
        directory.mkdir(exist_ok=True)
        self.path = directory / f"agent-{datetime.now():%Y%m%d-%H%M%S}.jsonl"

    def write(self, tip: str, **date):
        eveniment = {"ts": datetime.now().isoformat(timespec="milliseconds"), "tip": tip, **date}
        # Deschidem și închidem fișierul la fiecare eveniment: nu se pierde nimic la o oprire bruscă.
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(json.dumps(eveniment, ensure_ascii=False) + "\n")


def mcp_to_openai_tool(tool) -> dict:
    """Descrierea unui instrument MCP, în formatul cerut de modelul de limbaj."""
    # versiunile noi de FastMCP folosesc input_schema, cele vechi inputSchema
    schema = getattr(tool, "input_schema", None) or tool.inputSchema
    return {
        "type": "function",
        "function": {
            "name": tool.name,
            "description": tool.description or "",
            "parameters": schema,
        },
    }


def _hint(ann, snake: str, camel: str):
    """Valoarea unui indiciu; numele câmpului diferă între versiunile SDK-ului MCP."""
    if ann is None:
        return None
    for nume in (snake, camel):
        if hasattr(ann, nume):
            return getattr(ann, nume)
    return None


def tool_flags(tool) -> dict:
    """Indiciile (adnotările) unui instrument. Lipsa lor înseamnă: poate modifica și poate distruge."""
    ann = getattr(tool, "annotations", None)
    read_only = bool(_hint(ann, "read_only_hint", "readOnlyHint"))
    destructive = (not read_only) and _hint(ann, "destructive_hint", "destructiveHint") is not False
    return {"read_only": read_only, "destructive": destructive}


def truncate(text: str, limit: int = MAX_TOOL_CHARS) -> str:
    """Taie un rezultat prea lung, spunând modelului că a fost tăiat."""
    if len(text) <= limit:
        return text
    return text[:limit] + f"\n[... trunchiat: {len(text) - limit} caractere omise]"


def trim_history(messages: list[dict], max_turns: int = MAX_TURNS) -> list[dict]:
    """Păstrează mesajul system și ultimele `max_turns` ture.

    O tură începe la un mesaj `user` și conține tot ce urmează până la următorul `user`
    (inclusiv cererile de apel și rezultatele lor). Tăind doar la limita dintre ture,
    nu rămâne niciodată un rezultat de instrument fără cererea lui.
    """
    starts = [i for i, m in enumerate(messages) if m["role"] == "user"]
    if len(starts) <= max_turns:
        return messages
    return messages[:1] + messages[starts[-max_turns]:]


class Agent:
    def __init__(self, confirm=None):
        """`confirm(nume, argumente, distructiv) -> bool` decide dacă un instrument cu efecte
        poate rula. Fără `confirm`, instrumentele cu efecte sunt refuzate."""
        self.llm, self.model, self.provider = make_client()
        self.mcp = Client(SERVER)  # pornește server.py ca proces copil (stdio)
        self.confirm = confirm
        self.log = JsonlLog()
        self.tools = []
        self.flags = {}
        self.reset()

    def reset(self):
        """Conversație nouă: păstrăm doar instrucțiunile de sistem."""
        self.messages = [{"role": "system", "content": SYSTEM_PROMPT}]
        self.log.write("reset")

    async def __aenter__(self):
        await self.mcp.__aenter__()
        found = await self.mcp.list_tools()
        self.tools = [mcp_to_openai_tool(t) for t in found]
        self.flags = {t.name: tool_flags(t) for t in found}
        self.log.write("pornire", furnizor=self.provider, model=self.model,
                       instrumente=sorted(self.flags))
        return self

    async def __aexit__(self, *exc):
        await self.mcp.__aexit__(*exc)

    async def call_tool(self, call, pas: int) -> str:
        """Execută un apel cerut de model: verificări, confirmare, apel MCP, log."""
        nume = call.function.name
        try:
            args = json.loads(call.function.arguments or "{}")
        except json.JSONDecodeError as e:
            return self._rezultat(pas, nume, {}, f"Eroare: argumentele nu sunt JSON valid ({e}).", True)
        self.log.write("apel", pas=pas, nume=nume, argumente=args)

        flags = self.flags.get(nume)
        if flags is None:  # instrument care nu există în lista serverului
            text = f"Instrument necunoscut: {nume}. Disponibile: {', '.join(sorted(self.flags))}."
            return self._rezultat(pas, nume, args, text, True)

        if not flags["read_only"]:  # instrument cu efecte: cerem acordul utilizatorului
            aprobat = bool(self.confirm and self.confirm(nume, args, flags["destructive"]))
            self.log.write("confirmare", pas=pas, nume=nume, aprobat=aprobat)
            if not aprobat:
                return self._rezultat(pas, nume, args, "Utilizatorul a refuzat acest apel; nu a fost executat.", True)

        try:
            result = await self.mcp.call_tool(nume, args)
            text = "\n".join(b.text for b in result.content if hasattr(b, "text"))
            eroare = False
        except Exception as e:  # eroarea ajunge la model, care o poate explica
            text, eroare = f"Eroare la apelul {nume}: {e}", True
        return self._rezultat(pas, nume, args, text, eroare)

    def _rezultat(self, pas, nume, args, text, eroare) -> str:
        scurt = truncate(text)
        self.log.write("rezultat", pas=pas, nume=nume, eroare=eroare, text=scurt,
                       trunchiat=len(scurt) != len(text))
        print(f"  [instrument] {nume}({args}) -> {scurt[:150]}")
        return scurt

    def _final(self, text: str, **date) -> str:
        """Încheie întrebarea cu un mesaj al asistentului (și îl pune în istoric)."""
        self.messages.append({"role": "assistant", "content": text})
        self.log.write("raspuns", text=text, **date)
        return text

    async def ask(self, text: str) -> str:
        self.messages.append({"role": "user", "content": text})
        inainte = len(self.messages)
        self.messages = trim_history(self.messages)
        self.log.write("intrebare", text=text, mesaje_taiate=inainte - len(self.messages))

        vazute: dict[tuple, int] = {}  # (nume, argumente) -> de câte ori a fost cerut
        for pas in range(1, MAX_STEPS + 1):
            extra = {"tool_choice": TOOL_CHOICE} if pas == 1 and TOOL_CHOICE != "auto" else {}
            t0 = time.perf_counter()
            reply = create_chat(
                self.llm, model=self.model, messages=self.messages, tools=self.tools, **extra
            )
            usage = getattr(reply, "usage", None)
            self.log.write(
                "cerere_model", pas=pas, mesaje=len(self.messages),
                durata_ms=round((time.perf_counter() - t0) * 1000),
                prompt_tokens=getattr(usage, "prompt_tokens", None),
            )
            msg = reply.choices[0].message
            if not msg.tool_calls:  # răspuns final, în text
                return self._final(msg.content or "", pas=pas)

            # Detecția buclei: același apel cerut de prea multe ori în aceeași întrebare.
            chei = [(c.function.name, c.function.arguments) for c in msg.tool_calls]
            for cheie in chei:
                vazute[cheie] = vazute.get(cheie, 0) + 1
            if any(vazute[c] > MAX_REPEAT for c in chei):
                self.log.write("bucla_detectata", pas=pas, apeluri=[c[0] for c in chei])
                return self._final("(M-am oprit: modelul cere în mod repetat același apel.)", pas=pas)

            # Modelul cere instrumente: le păstrăm în istoric, le executăm, repetăm.
            self.messages.append({
                "role": "assistant",
                "content": msg.content or "",
                "tool_calls": [c.model_dump(exclude_none=True) for c in msg.tool_calls],
            })
            for call in msg.tool_calls:
                rezultat = await self.call_tool(call, pas)
                self.messages.append({"role": "tool", "tool_call_id": call.id, "content": rezultat})

        self.log.write("limita_pasi", pasi=MAX_STEPS)
        return self._final("(Am atins limita de pași a agentului.)")

"""Chatbot în linia de comandă, cu confirmare pentru instrumentele cu efecte. Rulare: python chat.py"""
import asyncio

from openai import APIConnectionError, APIStatusError

from agent import Agent


def cere_acord(nume: str, args: dict, distructiv: bool) -> bool:
    """Întreabă utilizatorul dacă agentul are voie să ruleze un instrument cu efecte."""
    eticheta = " [DISTRUCTIV]" if distructiv else ""
    raspuns = input(f"  ? Agentul vrea să ruleze {nume}({args}){eticheta}. Permiteți? [d/N] ")
    return raspuns.strip().lower() in ("d", "da", "y", "yes")


async def main():
    async with Agent(confirm=cere_acord) as agent:
        print(f"Furnizor: {agent.provider} | model: {agent.model}")
        print("Instrumente:", ", ".join(t["function"]["name"] for t in agent.tools))
        print(f"Fișier de log: {agent.log.path}")
        print("Comenzi: /reset (conversație nouă), /istoric, /iesire\n")
        while True:
            try:
                text = input("Tu: ").strip()
            except (EOFError, KeyboardInterrupt):
                break
            if text == "/iesire":
                break
            if text == "/reset":
                agent.reset()
                print("(conversație nouă; starea clădirii din server nu s-a schimbat)")
                continue
            if text == "/istoric":
                print(f"(istoric: {len(agent.messages)} mesaje)")
                continue
            if not text:
                continue
            try:
                print("Agent:", await agent.ask(text), "\n")
            except APIStatusError as e:
                print(f"Eroare HTTP {e.status_code}: {str(e.body or e.message)[:200]}\n")
            except APIConnectionError:
                print("Nu mă pot conecta la model (server oprit sau fără internet).\n")


if __name__ == "__main__":
    asyncio.run(main())

"""Rezumă un fișier de log JSONL al agentului.
Utilizare: python analyze_log.py [logs/agent-....jsonl]   (fără argument: cel mai recent)"""
import json
import sys
from collections import Counter
from pathlib import Path


def main():
    if len(sys.argv) > 1:
        path = Path(sys.argv[1])
    else:
        fisiere = sorted(Path("logs").glob("agent-*.jsonl"))
        if not fisiere:
            sys.exit("Nu există fișiere de log în folderul logs/.")
        path = fisiere[-1]

    tipuri, apeluri, erori, refuzuri = Counter(), Counter(), Counter(), 0
    durate, tokeni, stricate = [], [], 0
    with open(path, encoding="utf-8") as f:
        for linie in f:
            try:
                e = json.loads(linie)
            except json.JSONDecodeError:  # o linie stricată nu strică restul fișierului
                stricate += 1
                continue
            tipuri[e["tip"]] += 1
            if e["tip"] == "apel":
                apeluri[e["nume"]] += 1
            elif e["tip"] == "rezultat" and e.get("eroare"):
                erori[e["nume"]] += 1
            elif e["tip"] == "confirmare" and not e["aprobat"]:
                refuzuri += 1
            elif e["tip"] == "cerere_model":
                durate.append(e["durata_ms"])
                if e.get("prompt_tokens") is not None:
                    tokeni.append(e["prompt_tokens"])

    print(f"Fișier: {path}")
    print("Evenimente pe tip:", dict(tipuri))
    print("Apeluri pe instrument:", dict(apeluri) or "-")
    print("Apeluri cu eroare:", dict(erori) or "-", "| refuzuri ale utilizatorului:", refuzuri)
    if durate:
        print(f"Cereri către model: {len(durate)} | durata medie: {sum(durate) / len(durate):.0f} ms")
    if tokeni:
        print(f"Tokeni în prompt: primul {tokeni[0]}, ultimul {tokeni[-1]}, maxim {max(tokeni)}")
    if stricate:
        print(f"Atenție: {stricate} linii nu au putut fi citite.")


if __name__ == "__main__":
    main()

4. Partea B: instrumente cu efecte (modificatori)

4.1. Ce s-a schimbat în server

Priviți din nou server.py (secțiunea 3.3). Trei lucruri sunt noi:

Starea clădirii. Variabilele PORNITE (mulțimea dispozitivelor pornite) și TERMOSTAT trăiesc în procesul serverului (secțiunea 1.5). Orice apel set_* le modifică.

Adnotările. Constantele CITIRE, MODIFICARE și DISTRUGERE sunt dicționare date parametrului annotations= al decoratorului @mcp.tool. Instrumentele de citire declară readOnlyHint. set_device_state și set_thermostat declară destructiveHint=False (se pot anula prin alt apel) și idempotentHint=True; reset_building declară destructiveHint=True.

Validarea. set_thermostat folosește Annotated[float, Field(ge=10, le=30, description="...")]: tipul, limitele (ge = mai mare sau egal, le = mai mic sau egal) și descrierea intră în schema de intrare văzută de model. FastMCP verifică schema înainte de a rula funcția; la o valoare în afara limitelor, funcția nu se execută, iar rezultatul este o eroare de execuție a instrumentului (isError: true). Specificația MCP prevede ca erorile de validare să fie raportate astfel, ca modelul să se poată corecta (MCP - Tools).

O regulă de domeniu. set_device_state refuză pornirea unui dispozitiv dacă ar produce un conflict RIDICAT cu unul deja pornit. Refuzul este returnat ca dată ({"ok": false, "motiv": ...}), în același spirit ca „dispozitiv necunoscut" din Laboratorul 1.

4.2. Confirmarea în agent

Fluxul unui apel cu efecte, așa cum este implementat în Agent.call_tool:

Observații despre cod:

  • tool_flags citește adnotările și produce read_only și destructive. Dacă adnotările lipsesc, instrumentul este tratat ca modificator și distructiv (valorile implicite din secțiunea 1.6);
  • un instrument care nu există în lista serverului nu ajunge deloc la server: agentul întoarce modelului o eroare și lista instrumentelor valide;

5. Partea C: gestiunea stării

5.1. Istoricul crește continuu

Fiecare cerere retrimite tot istoricul (secțiunea 1.1). Consecințele sunt concrete: cresc tokenii din prompt (și, odată cu ei, durata și consumul cotei gratuite), iar la un moment dat conversația nu mai încape în fereastra de context a modelului. Verificați în python analyze_log.py: valoarea „primul" și „ultimul" din linia Tokeni în prompt.

Agentul nostru are trei mecanisme simple de control, definite în agent.py și configurate prin constantele de la începutul fișierului:

Constantă Mecanismul Protejează de
MAX_TURNS și funcția trim_history păstrează doar ultimele N ture din conversație istoric nelimitat
MAX_TOOL_CHARS și funcția truncate taie un rezultat de instrument mai lung de N caractere un singur rezultat uriaș
MAX_REPEAT și MAX_STEPS opresc agentul când același apel se repetă, respectiv după N pași bucle

5.2. Fereastra glisantă

O tură începe la un mesaj user și conține tot ce urmează până la următorul mesaj user: cererile de apel, rezultatele lor și răspunsul final. trim_history păstrează mesajul system și ultimele MAX_TURNS ture.

Tăiem doar la granița dintre ture, nu oriunde. Un mesaj tool fără mesajul assistant care conține tool_calls corespunzător (sau invers) este invalid: furnizorii refuză cererea cu eroare HTTP 400. O tură întreagă este întotdeauna consistentă.

Prețul este uitarea: ce a fost tăiat nu mai este în istoric, deci modelul nu-și mai amintește. „Și în 5 ore?" nu mai are sens dacă întrebarea la care se referă a fost eliminată. Alternativele (rezumarea turelor vechi, memorarea unor fapte importante în afara istoricului) sunt teme facultative.

5.3. Rezultate lungi și bucle

truncate taie rezultatul peste MAX_TOOL_CHARS caractere și adaugă la sfârșit o notă care spune că textul a fost tăiat, ca modelul să nu creadă că a primit tot. Evenimentul rezultat din log are trunchiat: true.

Oprirea buclelor are două nivele:

  • MAX_REPEAT: dacă modelul cere de mai mult de MAX_REPEAT ori același apel (același nume și aceleași argumente) în cadrul aceleiași întrebări, agentul se oprește și scrie evenimentul bucla_detectata. Nu execută apelul în plus: dacă modelul este blocat, un rezultat identic nu-l ajută;
  • MAX_STEPS: limita totală de pași, pentru bucle în care apelurile diferă puțin de fiecare dată (limita_pasi în log).
